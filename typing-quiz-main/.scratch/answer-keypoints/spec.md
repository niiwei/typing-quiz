# 关键词作答规格

Status: ready-for-agent

## Problem Statement

短句答案的完全匹配迫使学习者背诵非核心措辞；中英文空格差异也会误判。一条复合答案无法分次回忆。

## Solution

保留打字交互、空白初始卡片和解释型注释。使用免输入正文还原句子，允许显式拆分要点、逐段答出；忽略空格时只规范化匹配，不改变显示。

## User Stories

1. 作为学习者，我希望只输入必答要点，以避免背诵非核心措辞。
2. 作为学习者，我希望输入完整句子也通过，以接受自然表达。
3. 作为学习者，我希望内部空白不导致错误，以适应输入法差异。
4. 作为学习者，我希望未作答卡片保持空白，以保持现有视觉。
5. 作为学习者，我希望分次、逆序回答要点，以按回忆顺序作答。
6. 作为学习者，我希望已答片段按原文位置显示，以理解完整表达。
7. 作为学习者，我希望重复提交不加分，以保持进度准确。
8. 作为学习者，我希望相同要点同时点亮所有对应项，以免反复输入。
9. 作为学习者，我希望部分完成仍进入复习，以补齐遗漏。
10. 作为编辑者，我希望通过按钮标记免输入和拆分，以减少手工语法负担。
11. 作为编辑者，我希望预览正文及每个必答要点，以检查学习目标。
12. 作为编辑者，我希望保留独立解释注释，以补充含义。
13. 作为编辑者，我希望保存、重新编辑及导出导入不丢结构，以复用题库。
14. 作为旧题用户，我希望原有标记字面量不被自动解释，以保护旧题。
15. 作为 agent 使用者，我希望 JSON 格式和校验规则明确，以可靠生成题库。
16. 作为编辑者，我希望非法语法提示行与位置，以快速修正。

## Implementation Decisions

### 编辑语法

- 每行一条答案。`{{文字}}` 为免输入片段；括号外为必答文字；`||` 划分作答要点；末尾 `#注释#` 为独立解释。
- 非嵌套语法。免输入片段归属其所在要点。注释在拆分之前识别；注释内部的花括号、竖线均为普通文字。
- 反斜线转义反斜线、井号、花括号、竖线；其他反斜线组合按原文保留。JSON 仍遵循 JSON 自身的反斜线编码。
- 未闭合标记、空段、仅含免输入文字的要点报错，不保存部分结果。相同要点和相同答案不做唯一性校验，不静默去重。
- 原有末尾注释语义不变。新语法仅在显式 v2 模式启用；旧题编辑保持 legacy，升级需编辑者主动选择并预览。
- 编辑器增加“设为免输入”“在此拆分”及实时预览；新增打字题默认 v2。选区跨段或包含既有标记时禁止包裹并提示，不生成嵌套语法。

### 数据契约

- 每条新答案携带 `formatVersion: 2`、`content`、可空 `comment` 和 `parts`。
- `parts` 为有序要点数组，每项有 `segments`；每个 segment 为 `kind`（required 或 context）及非空 `text`。索引在单次作答期间作为要点身份。
- `content` 是全部片段 text 按序拼接的完整正文，不含标记；comment 独立。服务端校验 content 与 parts 一致；不一致拒绝，不能静默猜测。
- 未携带版本或结构的旧答案保持旧数据含义；未知版本拒绝并提示。旧 answers 和 answerList 导入继续支持。
- 新结构以可空附加字段保存，旧行无需重写；所有详情、编辑、复制、导入、导出链路保留版本及片段。数据库迁移可重复执行，不删除旧列。
- v2 校验接口返回所有匹配的 answerId 与 partIndex 列表；旧客户端响应保留原字段，新客户端只消费列表。无匹配返回空列表。用户权限沿用现有检查。

### 匹配规则

- 忽略空格开启时，两端移除所有 Unicode White_Space 字符及 BOM；关闭时保留空格差异。大小写、标点仍按现有独立开关处理，前后端相同，不允许后端兜底绕过关闭的开关。
- 对每个要点接受必答片段拼接和该要点完整正文；对整条接受所有必答片段拼接和完整正文。解释不参加任何候选。
- `降低成本{{、}}||提高效率` 可用“降低成本”“提高效率”分答，或“降低成本提高效率”“降低成本、提高效率”整答。标点关闭时仍接受上述两个明确候选，但不自由删除输入中的任意标点。
- 不使用子串、模糊或语义匹配；不支持任意多个片段组合，除非组合恰好就是某个完整候选。
- 单次输入扫描全部答案及要点，一次合并全部命中后更新 UI 和计数，再判断结束；不能首个命中即返回。已完成项幂等。
- 规范化为空的输入不能命中；符号答案在移除符号后为空时提示关闭忽略标点，不能把空串当答案。

### 展示与复习

- 初始卡片保持原实现视觉，不加字、数字或额外说明；部分命中后在未答要点位置放固定宽度占位，不泄漏长度。
- 已答要点展示完整片段并保持原顺序，context 不受隐藏注释开关影响。解释型注释仅在整条完成或结算时按现有规则展示，防止提前提示。
- 顶部按完整答案计数，部分完成不加分。部分命中反馈“答对一个要点”；全重复才提示“已回答”。
- 结算展示已答与遗漏的不同状态；完成分数只计算全答完的答案。沿用测验级复习模型，不引入答案级调度；含未完成答案的测验保留现有复习入口，不得因部分命中认定全部掌握。
- 片段状态在本次练习和结算保留；下一次复习全部从未作答开始。不新增跨刷新恢复能力；已有组合练习切换行为不得退化。
- 答案和注释作为文本渲染，不能执行导入内容中的 HTML。

## Testing Decisions

- 优先通过创建/导入—读取—校验—作答—结算—导出—重新导入的用户路径验收；纯解析和规范化使用共享样例补齐边界。
- 已有 Spring Boot Test 依赖但无测试目录；Java/Maven 本机当前不可运行。首票建立隔离测试环境，禁止连接现有数据库或带真实密钥配置。
- 后端以真实 DTO/服务/测试数据库覆盖持久化往返；前端以真实页面事件验证逐段状态及空白视觉。不能用只测新 helper 代替实际消费验证。
- 同一批输入在前端本地和后端回退得到相同命中集合；至少包括全角空格、制表、NBSP、大小写及标点开关。
- 每票先证明回归用例失败，再实现通过；包含旧打字题和填空题回归，错误输入、重复命中、全匹配、多答案重合、非法导入原子性。

## Out of Scope

AI 判分、同义词推断、任选 N 项通过、强制顺序、分数权重、填空题结构升级、答案级复习调度、线上部署及推送。

## Further Notes

用户要求拆票后停止供检验，当前 ready-for-agent 表示规格可执行，不代表获得开始实现许可。技术细节为根据已确认产品行为制定的执行方案，可在用户检验时调整。
