# 01 — 建立个人数据安全边界与 PAT

**What to build:** 用户可以在设置页创建、查看元数据并撤销多个命名 PAT；网页 JWT 和 Agent PAT 各自只能进入允许的接口，任何个人资源都不能被匿名或其他账号访问。

**Blocked by:** None — can start immediately

**Status:** completed

- [x] 开始实现前运行 Java 与静态浏览器基线；Java 6/6、浏览器 9/9 通过。
- [x] 先更新工作区规则，明确 MCP 模块的用途、命名、构建产物和清理约定。
- [x] 公开页面、注册、登录及既有匿名埋点保持可用，其他个人数据 API 缺失或无效 JWT 时返回 401。
- [x] 已认证用户访问题库、答案和分组资源时按 userId 隔离；Agent 跨用户访问统一 404。
- [x] 用户可创建多个命名 PAT；完整令牌只显示一次，持久化数据只保存 SHA-256 哈希，并记录创建时间和最近使用时间。
- [x] 撤销单个 PAT 后它立即失效，不影响网页 JWT 或其他 PAT。
- [x] PAT 只能访问版本化 Agent API，不能管理 PAT、进入后台或调用原网页 API。
- [x] 设置页完成 PAT 列表、创建、一次性复制提示和撤销流程。
- [x] 提供只读重复分组预检 SQL，并在服务层建立按用户、去空格且不区分大小写的唯一规则。
- [x] Java HTTP 集成测试覆盖身份缺失、PAT 生命周期与路径隔离。
